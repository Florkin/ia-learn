# ia-learn : plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Livrer le socle de quatorze modules d'un dépôt de formation à l'IA engineering, chacun vérifié par
exécution réelle.

**Architecture:** Un paquet `assistant/` porte la version de référence de chaque brique du fil rouge. Chaque
module (`modules/NN-slug/`) contient une leçon, un squelette d'exercice, un check et des approfondissements.
Un paquet `course/` fournit l'outillage commun des checks.

**Tech Stack:** Python 3.12, uv, `openai` 3.x, numpy, Chroma 1.5, LangChain 1.4, PyTorch 2.14, `mlx-lm`,
`transformers` + `peft`, Ollama (`granite4.1:3b`, `bge-m3`).

**Spec:** `docs/superpowers/specs/2026-10-06-ia-learn-design.md`

**Statut :** exécuté le 2026-10-06, les dix-sept tâches sont terminées. Les écarts au plan sont reportés dans
la spec.

**Exécution :** dans la session courante, sans sous-agent, à la demande de Tristan (mode autonome). Le plan
fixe les interfaces et les critères d'acceptation. Le corps des fonctions est écrit à l'exécution, parce que
plusieurs bibliothèques sont plus récentes que ce que l'auteur du plan connaît et que chaque appel doit être
vérifié contre la version installée.

## Global Constraints

- Leçons, README et messages affichés à l'apprenant en français. Code, identifiants, noms de fichiers et
  commentaires en anglais.
- Tout fichier est lu et écrit avec `encoding="utf-8"` explicite (le collègue peut être sous Windows).
- Aucune clé d'API dans git. `corpus/` et `.data/` restent hors git.
- Une leçon se lit en dix minutes, un module se fait en 30 à 45 minutes.
- La brique de référence d'un module expose les mêmes noms de fonctions que son exercice.
- Un check n'importe jamais le code d'un apprenant pour un autre module.
- Dépendances lourdes dans les groupes uv `langchain` et `training`.
- Chaque module est accepté quand `course.selftest` constate les deux résultats : échec sur le squelette,
  succès sur la référence.

## Review Focus

1. Ollama arrêté ou modèle non téléchargé : le check affiche une consigne en français, sans trace Python.
2. `LEARNER` absent de `.env` : message qui dit quoi écrire et où.
3. Fonction de l'apprenant qui renvoie `None` ou un mauvais type : le check dit ce qu'il attendait.
4. Check relancé après succès, index reconstruit : ni ligne de progression en double, ni passage en double.
5. Lignes commençant par `#` dans un bloc de code : le découpage ne les prend pas pour des titres.

Les points 1 à 4 sont couverts par `course/harness.py` (tâche 1) et le test d'idempotence du module 6. Le
point 5 est un cas du check du module 5.

## Interfaces

```python
# assistant/config.py
ROOT: Path; DATA_DIR: Path; CORPUS_DIR: Path
settings: Settings  # learner, chat_base_url, chat_api_key, chat_model, embed_base_url, embed_api_key,
                    # embed_model, openrouter_api_key, hosted_models, finetune_backend

# assistant/llm.py
def client(base_url: str | None = None, api_key: str | None = None) -> OpenAI
def build_messages(system: str, history: list[dict], question: str) -> list[dict]
def ask(question: str, history: list[dict] | None = None, system: str = ...) -> str
def stream_answer(question: str, system: str = ..., temperature: float = 0.0) -> Iterator[str]
def variants(prompt: str, temperature: float, n: int = 3) -> list[str]
class QuestionAnalysis(BaseModel): language: Literal["fr", "en"]; about_laravel: bool; search_query: str
def analyze_question(question: str) -> QuestionAnalysis
def cost(prompt_tokens: int, completion_tokens: int, price_in: float, price_out: float) -> float
def compare(question: str, targets: list[Target]) -> list[Run]

# assistant/corpus.py
@dataclass(frozen=True) class Page: slug: str; section: str; title: str; text: str
SAMPLE_PAGES: tuple[str, ...]
def ensure_corpus() -> Path
def load_pages(sample: bool = False) -> list[Page]

# assistant/embeddings.py
def embed(texts: list[str]) -> np.ndarray            # shape (n, d)
def cosine_similarity(a, b) -> float
def rank(query: str, candidates: list[str]) -> list[tuple[str, float]]

# assistant/chunking.py
@dataclass(frozen=True) class Chunk: id: str; source: str; section: str; heading: str; text: str
def chunk_markdown(text: str, source: str, section: str = "", max_words: int = 300) -> list[Chunk]
def chunk_corpus(sample: bool = False) -> list[Chunk]
def search(query: str, chunks: list[Chunk], vectors: np.ndarray, k: int = 5) -> list[tuple[Chunk, float]]

# assistant/store.py
def open_collection(path: Path, name: str = "docs") -> Collection
def build_index(chunks: list[Chunk], collection: Collection) -> int
def query_index(question: str, collection: Collection, k: int = 5, where: dict | None = None) -> list[Chunk]
def reference_index() -> Collection                  # full corpus, built on first use

# assistant/rag.py
@dataclass class Answer: text: str; sources: list[Chunk]
def build_prompt(question: str, passages: list[Chunk]) -> list[dict]
def answer(question: str, k: int = 5) -> Answer

# assistant/evaluation.py
def load_golden() -> list[dict]                      # {"question": str, "sources": [slug, ...]}
def hit_rate(results: list[list[str]], expected: list[list[str]], k: int = 5) -> float
def mrr(results: list[list[str]], expected: list[list[str]]) -> float
def evaluate(retriever: Callable[[str], list[str]], golden: list[dict], k: int = 5) -> dict

# assistant/retrieval.py
class BM25: def __init__(self, texts: list[str]); def search(self, query: str, k: int) -> list[int]
def vector_search(question: str, k: int = 5) -> list[Chunk]
def reciprocal_rank_fusion(rankings: list[list[str]], k: int = 60) -> list[str]
def hybrid_search(question: str, k: int = 5) -> list[Chunk]

# assistant/rag_langchain.py
def build_retriever(k: int = 5)
def build_chain(k: int = 5)                          # Runnable: str -> str

# assistant/agent.py
@dataclass class AgentResult: answer: str; tool_calls: list[dict]; steps: int
def run_agent(question: str, max_steps: int = 4, complete: Callable | None = None) -> AgentResult

# assistant/classifier.py
def load_dataset(seed: int = 0) -> Dataset           # X_train, y_train, X_val, y_val, labels
def make_model(n_features: int, n_classes: int, hidden: int = 0) -> nn.Module
def train(model, data: Dataset, epochs: int = 30, lr: float = 1e-3, batch_size: int = 64) -> list[dict]

# assistant/finetune.py
def build_examples(chunks: list[Chunk]) -> list[dict]      # {"messages": [...]}
def split_examples(examples: list[dict], valid_ratio: float = 0.1, seed: int = 0) -> tuple[list, list]
def train(train: list[dict], valid: list[dict], out_dir: Path, iters: int = ..., backend: str | None = None) -> Path
def generate(prompts: list[list[dict]], adapter_dir: Path | None = None, backend: str | None = None) -> list[str]

# course/harness.py
class Check:
    def __init__(self, check_file: str)       # resolves the module, loads exercise per COURSE_MODE
    exercise: ModuleType
    def step(self, label: str)                # context manager, prints the outcome, exits 1 on failure
    def finish(self) -> None                  # records progress (learner mode only)
```

`COURSE_MODE` vaut `learner` (défaut, copie dans `learners/<prénom>/`), `skeleton` (charge
`modules/NN/exercise.py` tel quel) ou `reference` (charge la brique de référence déclarée par le check).

## Tâches

Chaque tâche de module suit les mêmes étapes, dans cet ordre.

- [ ] Écrire `check.py` (assertions déterministes d'abord, appels réels ensuite).
- [ ] Écrire `exercise.py` (squelette, `NotImplementedError`, démonstration dans `__main__`).
- [ ] Constater l'échec : `COURSE_MODE=skeleton uv run modules/NN-slug/check.py` sort en code 1.
- [ ] Écrire la brique de référence dans `assistant/`.
- [ ] Constater le succès : `COURSE_MODE=reference uv run modules/NN-slug/check.py` sort en code 0.
- [ ] Lancer la démonstration du module et lire le résultat.
- [ ] Écrire `LESSON.md` et `DEEPER.md` à partir de ce qui a réellement été observé.
- [ ] Commit.

### Tâches 3 à 16 : modules 1 à 14

| Tâche | Module | Critères du check |
|---|---|---|
| 3 | `01-first-call` | `build_messages` : système en premier, historique conservé, question en dernier. `ask` répond « pong » à une consigne triviale et retrouve un prénom donné dans l'historique |
| 4 | `02-generation-settings` | `stream_answer` est un générateur d'au moins deux morceaux de texte. `variants` à température 0 donne des réponses identiques, à température haute au moins deux réponses différentes |
| 5 | `03-structured-output` | `analyze_question` renvoie un objet validé. Langue correcte en français et en anglais, hors sujet détecté, requête de recherche en anglais non vide |
| 6 | `04-embeddings` | `cosine_similarity` exacte sur des vecteurs connus. `embed` renvoie une matrice (n, d). `rank` place la paraphrase en tête, y compris d'une langue à l'autre |
| 7 | `05-chunking-search` | Passages non vides, taille bornée, titre conservé, aucun mot perdu, `#` dans un bloc de code ignoré. `search` retrouve la page attendue |
| 8 | `06-vector-store` | Nombre de passages indexés exact, reconstruction sans doublon, filtre par section respecté, page attendue retrouvée |
| 9 | `07-first-rag` | Le prompt numérote les passages et contient la question. La réponse cite au moins un passage et ses sources contiennent la page attendue |
| 10 | `08-evaluation` | `hit_rate` et `mrr` exacts sur des cas écrits à la main. `evaluate` donne les mêmes chiffres que la référence sur le jeu de questions. Livre aussi `data/golden.jsonl` |
| 11 | `09-better-retrieval` | `reciprocal_rank_fusion` exacte sur des classements connus. `hybrid_search` renvoie k passages distincts et retrouve un identifiant exact que la recherche vectorielle seule classe moins bien |
| 12 | `10-hosted-models` | `cost` exact. `compare` renvoie latence, tokens et coût par cible. OpenRouter appelé seulement si la clé est présente |
| 13 | `11-langchain` | La chaîne répond avec une citation. Son retriever renvoie les mêmes passages que `query_index` sur l'index de référence |
| 14 | `12-tools-agents` | Avec un modèle simulé qui réclame toujours un outil, la boucle s'arrête à `max_steps`. Avec le vrai modèle, une question Laravel déclenche une recherche |
| 15 | `13-training` | La perte d'entraînement baisse, l'historique a une entrée par époque, la précision de validation dépasse un seuil mesuré à l'implémentation |
| 16 | `14-fine-tuning` | Exemples au format conversation, étiquettes dans l'ensemble autorisé, aucun passage commun entre entraînement et validation. Précision après affinage supérieure à la précision avant. Vérifié avec `mlx` puis avec `peft` |
